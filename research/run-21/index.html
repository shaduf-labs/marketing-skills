Research report · 11 October 2026 · Run 21

A welcome-email brief is a draft, not a configured flow

Keep Core Haines emails as a conditional source-inspected candidate for our proposed five-email post-signup welcome draft. Start with an owner-maintained brief and reviewed prompt. Neither route was run or compared.

Decision for one approved draft

Use an owner-approved, non-personal brief to write a local Markdown hypothesis. The source's timing, exit and metric fields are prompts to review, not verified recipient rules, performance targets or send-ready settings. A named owner must approve proof, terms and the exact CTA URL. Any import, ESP setup, test, schedule or send needs a separate authorization.

What was inspected

On 11 October, the mutable selected emails/SKILL.md displayed 2.1.3. The returned selected text was 313 lines and marked crawled today. I also read its directly routed welcome sequence template and per-email copy guidelines, returned as crawled four and two days earlier. These mutable pages are bounded observations, not an immutable selected-file pin or a complete package inventory.

No path-history/API retry, directory enumeration, installation, local product-context read, email account connection or send occurred. The selected-file SHA/date, latest modifying commit, full 2.1.1→2.1.3 diff and current reference inventory remain unknown. The file-attributable 2.1.0 change commit remains historical; it is not a latest main pin.

This limits what this review can claim; it does not establish that every suggestion is wrong.

One-page owner worksheet for the first route

1 · Approved factsRecord brief ID, owner, audience, factual signup trigger, approved product promise, terms, evidence IDs and exact destination URL. Missing facts stay “not supplied.”
2 · Five draft rowsFor emails 1–5, write purpose, proposed delay, subject, preview, body, one CTA and URL, any segment condition, claim-to-proof link and unresolved question. Unsupported template beats are holds.
3 · Measurement questionsRecord goal-event definition, denominator, window, source, authorized aggregate baseline or “not supplied,” competing emails and journey overlap. Generic source rates are not targets.
4 · Review, then separate releaseRecord named marketing/brand and recipient-policy reviews, proof and URL checks, and specialist checks where required. Keep status “local draft only” until a later explicit ESP/action approval.

This worksheet is pool-proposed, not source-enforced. The owner-maintained template is the first route for one local draft because its fields and hold markers can be controlled directly; that is a design choice, not an observed speed or quality advantage. A third-party skill could be compared later only against repeated, consented omissions on the same approved cases after a full revision, host, data and reviewer check. Neither route was executed here.

What would change the decision

Remove or further narrow the card if a verified intended revision requires recipient data, a live account, ESP configuration or sending to produce this bounded draft, or cannot keep unsupported claims and metrics separate. Consider a controlled template-versus-skill draft comparison only if recurring consented cases reveal specific omissions and named reviewers can inspect both outputs. No such evidence is present.

There was no real audience, consent basis, list, URL, campaign, performance data, local product context, ESP or host installation in this run. No legal, deliverability, conversion, safety, compatibility, quality or performance outcome is established. Run 6, Run 15 and Run 16 remain dated historical observations, not silent 2.1.3 updates.
