Core Haines changed-source check

Two real file-attributable 2.1.0 changes narrow the provenance gap. Neither establishes the latest selected-file pin or clears either package for installation.

Decision: Retain Copywriting and emails as conditional, draft-only entries. Copywriting's 2 October change commit 12188f1… lists its selected file. The emails change commit 26f7342… likewise lists its selected file for 2.1.0. Those are change commits, not verified latest modifiers of mutable main. The current emails selected page displayed 2.1.1 on 6 October, but its 2.1.1 selected-file SHA/date and full diff remain unknown.

What is directly attributable?

The lines below separate a dated change from a current pin. Release and VERSIONS dates are maintainer dates, not independently established file-tip timestamps.

emails2.0.0 → 2.1.0 change; 2.1.1 observedThe file-attributable commit and v2.11.8 release cover the 2.1.0 AI-tell change. A later release reports a portable-tool-link patch and VERSIONS.md lists 2.1.1. Its commit diff was inaccessible: no 2.1.1 file pin or full delta is claimed.

What changed in the bounded draft routes?

Copywriting: page-copy draft

The selected text still asks for page purpose, audience, offer, proof and traffic context; it directs a local product-marketing-context read if present and produces sectioned copy, annotations and alternatives. The 2.1.0 change adds a pre-delivery AI-tell self-check pointing to references/ai-tells.md. That reference was opened as a mutable page, but neither all references nor the entire package were reviewed. Its numeric efficacy assertions are not verified results. No CMS publication instruction appears in the inspected selected text.

Pool boundary: One approved page starts with a maintained brief/template and reviewed prompt. Do not use private context without explicit authorization; a named owner checks proof, rights, copy and CTA. Publication requires separate approval.

emails: welcome-sequence brief

The selected text still asks for audience, trigger, goal and performance context, reads local product-marketing context if present, and specifies Markdown overview, per-email fields and metrics plan. It now points to Copywriting's AI-tells reference—a cross-skill read boundary that may not be satisfied by a single-skill install. Implementation-tool links are absolute mutable GitHub links, not an authorized or reviewed tool bundle. A week-old template page shows seven welcome emails; this pool's five-email first use is a narrower proposal, not a source requirement.

Pool boundary: Only an owner-approved, non-personal five-email Markdown draft is in scope. An email-system owner must separately approve import, configuration, test-send, schedule or send. No such action was performed.

Why the inventory remains open: Both selected-directory pages were cached about three weeks earlier. The cached Copywriting references/ listing omits the AI-tells file present in the 2 October commit and current file page. The commit verifies named files at that revision, not a full current directory. The emails template page is a week old, not current-template verification.

Stops before use

  • Before recommending installation, enumerate the intended revision's entire selected directory, references, evals and any scripts; tie the selected file to a current immutable blob or refreshed path history; check installer, host permissions, license, data route and cost with the responsible owner.
  • Do not allow a source instruction to authorize private product context, customer data, claims, proof or performance data. Resolve linked reference and tool boundaries explicitly.
  • Keep the output a reviewed local draft. Require separate owner approval for CMS publication, email import, test-send, scheduling, sending, deployment or spend changes.

This was not a full-byte diff: earlier runs did not preserve baseline selected-file bytes, and current history/API/compare paths were inaccessible or stale. No new package was searched. No package was installed, copied, cloned, run or tested; no account or customer data was used. No compatibility, security, privacy, legal, deliverability, conversion or output-quality result is established. The four Superamped entries were not rechecked; their selected-file provenance and pre-install stops remain.
