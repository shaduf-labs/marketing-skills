One-skill install: documented scope, not a tested payload

The repository documents named-skill selection and a one-skill ZIP design. Neither document shows the files an actual CLI install or archive would place in a particular host. Keep four conditional active cards, two historical nonrecommendations, and the stop before any install recommendation.

Decision

For one approved non-personal brief, start with an owner-maintained template and reviewed prompt. A local Markdown page or email draft does not require an account or a whole-repository install in the inspected instructions. That is a bounded source finding, not a host guarantee. Do not install, connect an account, read local product context, publish or send from this evidence.

What each route actually documents

Named CLI selectionThe repository README gives npx skills add coreyhaines31/marketingskills --skill cro copywriting as a specific-skills example. The linked installer README defines --skill as named selection and --list as enumeration. Project/global and symlink/copy modes are documented; none was executed here.
One-skill release ZIPThe source-owned packaging design says one archive contains the named skill folder, authored references/scripts/assets and license, excluding other skills and the rest of the repository. It says the archive does not add a CLI, MCP server, credentials or marketing context. The author says live client upload remains unverified.
Full-library routesThe repository's plugin and clone/copy options select or copy the wider library. That does not make them a prerequisite for one local draft. A documented route is not an observed install, exact file inventory, permission set or host compatibility result.

Substituting --skill emails in the example is a syntax inference, not a command run for this research. No ZIP, manifest or CLI-selected files were downloaded, hashed or inspected.

Stop before an install or action

The repository calls product-marketing a conceptual foundation, and both selected files conditionally direct a local product-marketing-context read if present. Neither inspected selected-file passage expressly requires installing that skill, a whole repository, credentials, ESP setup or a send to produce a local Markdown draft. Local context still needs authorization; a different host or revision could behave differently.

Before recommending an install or same-brief comparison: pin the intended selected revision; enumerate and hash the exact archive or CLI payload, including reference resolution; review installer version, mode, host and permissions; obtain a consented non-sensitive brief and read scope; use fixed omission and claim-to-proof criteria against the owner template. A named owner reviews proof and exact CTA. Recipient-policy and ESP owners separately decide eligibility, consent, suppression, overlap, timing, import, setup, test, schedule and send. No brief, package, archive, CLI, account, draft, send or outcome was tested. Documentation alone establishes no compatibility, security, privacy/legal safety, quality, deliverability or marketing result.
