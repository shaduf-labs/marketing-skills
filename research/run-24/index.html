Welcome-email links: source-read, not install-verified

The emails card stays conditional and draft-only. Linked reference pages were read; their availability inside a single-skill install, and any host or provider behavior, remain unverified. Do not follow implementation routes for the proposed welcome draft.

Decision

For one approved, non-personal post-signup question, start with the owner's maintained brief/template and a reviewed prompt. Our five-message Markdown draft is a pool hypothesis, not a source-required length or configured flow. A named owner reviews proof, terms and the exact CTA URL. Recipient-policy and ESP owners separately decide eligibility, consent, suppression, overlap, timing and any import, configuration, test, schedule or send. No install or email-system action is authorized.

What was read

The mutable selected emails file displayed version 2.1.3 and was returned as crawled on 14 October. It directs reads of sequence templates, email types and copy guidelines. Those pages were read on 14 October. The seven-message welcome sequence is a source example, not the pool's five-message requirement. The email-types material concerns lifecycle audits, not this narrow draft. Copy-guideline performance ranges are unsourced in the inspected text and are not pool targets.

The selected file also points to Copywriting's AI-tells page. It was read as cross-skill style guidance, not as a validated detector. Its presence at a mutable URL does not show that an emails-only install includes it. The separate tool registry and setup page were also read. The registry is an implementation route; setup discusses account connection and credentials, not a prerequisite for producing a Markdown draft.
